# SameCast 电视端 App（Android）

电视端只装这一个 App。它**不是**一个投屏设备，而是网关的一个"播放端"：
自动找到网关 → 接收播放指令 → 播放并上报进度与暂停状态。

- 手机投屏：系统投屏按钮只看到网关那**一台**虚拟设备（`SameCast`）
- 多台电视：同时播放同一个流，任意一台按遥控器「确定」暂停，全部一起暂停
- 自带播放界面：待机页 / 载入中 / 底部播放控制栏 / 暂停 / 失败重试全在电视上，遥控器可操作，不依赖 Kodi
- B 站小电视：网关解析 B 站链接后，电视按 DASH/MP4 播放，顶部显示「来自 B 站小电视 · N 台电视同步」；扫码登录可选，不登录也能看
- 控制栏带同步与清晰度面板：能看每台电视与整组的实时偏差、一键「立即对齐」，也能限制最高清晰度、调画面比例
- 开机自启，连上网关就待命；被别的投屏抢占时自动让出画面，对方结束后自动回到待机页

## 构建 APK（不需要 Android Studio）

```bash
cd android
./build.sh
# 产物：app/build/outputs/apk/debug/SameCast-0.6.0-debug.apk
```

`build.sh` 会自动选构建方式：

| 本机环境 | 构建方式 |
|---|---|
| 有 JDK 17 + Android SDK 34（设了 `ANDROID_SDK_ROOT`，或写成 `local.properties` 里的 `sdk.dir`） | `./gradlew assembleDebug`，十几秒 |
| 只有 docker | `Dockerfile.build` 镜像（约 1GB，含 SDK + Gradle） |

两种都需要联网下载 Gradle 依赖（AndroidX Media3）。想自己加代码用 Android Studio 打开 `android/` 也行。

## 安装到电视

```bash
adb connect <电视IP>:5555
adb install -r app/build/outputs/apk/debug/SameCast-*.apk
```

批量装到多台电视（免遥控器二次确认、装完自动拉起）：

```bash
SAMECAST_DEVICES="<电视1 IP>:5555 <电视2 IP>:5555 ... <电视N IP>:5555" ../toolchain/install-tv.sh
```

没有 ADB 就用 U 盘：把 APK 拷到 FAT32 U 盘 → 电视文件管理器/应用调试里安装
（创维 55A3：工程模式 → 应用调试，密码 `69573028`；微鲸 W40F：设置里允许未知来源 → 本地播放里装）。

## 首次运行

App 打开后显示「正在查找 SameCast 网关…」，2–4 秒内会自动通过 SSDP 找到同一局域网里的网关，
然后显示「已连接 SameCast 网关」并进入等待投屏状态。**不需要在电视上输入任何 IP。**

网关侧会自动注册这台电视（`/api/recv/<id>/...` 动态创建），无需改配置重启。

## 工作方式

| 方向 | 接口 |
|---|---|
| 发现网关 | SSDP `M-SEARCH` + `ST: urn:samecast:service:Gateway:1` |
| 收指令 | `GET /api/recv/<id>/poll?since=<seq>` （350ms 轮询） |
| 上报状态 | `POST /api/recv/<id>/state` `{"state":"playing","position":12.3}` |
| 上报遥控操作 | `POST /api/recv/<id>/command` `{"cmd":"pause","position":12.3}` |
| 手动对齐 | `POST /api/control` `{"cmd":"resync"}`（或 `/api/recv/<id>/command` 同参数），全组立刻 seek 回同一位置 |

和网页接收端 `/tv` 用的是同一套协议，所以可以先在浏览器里验证网关，再上电视。

## 实现要点

- **ExoPlayer (Media3)** 播放 HLS/MP4，硬件解码；不依赖系统播放器
- 遥控器按键分两层（详见下方「界面」）：控制栏收起时 ←/→ 直接快退/快进 10 秒；按确定/上/下/菜单呼出控制栏后，←/→ 改为在按钮间移动、确定执行当前按钮。遥控器独立的播放/暂停键任何时候都是全组播放/暂停，所有操作都走网关，和手机投屏同一条链路
- 进度每 800ms 上报一次；网关侧按设备基准延迟做倍速微调，偏差大才 seek
- 清晰度面板用 `DefaultTrackSelector` + `setMaxVideoSize` 限最高分辨率（自动 / 1080p / 720p / 480p），选择存 SharedPreferences
- 画面比例用 `PlayerView.resizeMode`（适应 / 拉伸 / 原始）
- 同步面板每 500ms 读 `/api/status`，用各电视上报位置减整组位置算实时偏差，毫秒展示
- B 站片源优先走 media3 的 DASH（`media3-exoplayer-dash`）；`ResolvingDataSource` 只给 `bilivideo` / `bilibili` 域名的请求补 `Referer` 和 UA，绕开 CDN 防盗链，普通 MP4 直链也能播
- 明文 HTTP 已允许（`usesCleartextTraffic`），局域网直连不需要证书
- `minSdk 21`（Android 5.0），覆盖微鲸 W40F 的 Android 5.x

## 可能踩的坑

| 现象 | 处理 |
|---|---|
| 一直「正在查找 SameCast 网关」 | 先确认电视和网关在同一网段（`ping` 得通）；网关回包必须来自 UDP 1900 端口，旧版网关用临时端口回包时，部分电视（如微鲸 W40F）会丢包导致一直找不到 |
| 播放失败 `ERROR_CODE_IO_BAD_HTTP_STATUS` | B 站片源已由网关解析并补好请求头；其他 App 的加密/防盗链直链仍可能播不了，需要网关侧转封装 |
| 花屏/黑屏但声音正常 | 老芯片硬解 H.264 High profile 4K 吃力，让网关转成 1080p 中继 |
| 装不上 | 酷开系统要先用「应用调试」打开安装权限；微鲸要在设置里允许未知来源 |

## 界面

电视端没有按钮菜单，全部靠遥控器，状态都在画面上：

| 场景 | 电视上看到 |
|---|---|
| 等投屏 | 品牌页、电视型号、网关连接状态（绿点=已连）、支持的 App 提示、版本号 |
| 载入中 | 居中转圈 + 「正在载入片源…」提示 |
| 播放中 | 全屏画面；顶部一行片名 +「来自手机投屏 / 来自 B 站小电视 · N 台电视同步」，按确定/上/下/菜单呼出底部控制栏（进度条、播放/暂停、快退/快进 10 秒、音量、同步、清晰度、更多），播放中 4 秒自动收起 |
| 暂停 | 画面中央「已暂停」+ 大播放键，控制栏常驻；提示「按「确定」继续 · 所有电视会一起继续」 |
| 播放结束 | 「播放结束」，提示在手机上换一集，电视自动跟随 |
| 播放失败 | 「无法播放这个视频」，提示在手机上重新投屏一次 |
| 同步 | 列出每台电视与整组的偏差（毫秒），绿色=已对齐、黄色=正在校准；「立即对齐」强制全组 seek 回同一位置 |
| 清晰度 | 自动 / 1080p / 720p / 480p；显示当前画面分辨率、编码、码率 |
| 被其他投屏抢占 | 「已被其他投屏接管」，SameCast 自动让出画面/声音；对方投屏结束后自动回到待机页 |
| 网关断线 | 右上角黄色「未连接网关」+「与网关的连接中断，正在重连…」；恢复后自动重新同步 |

控制栏打开时默认高亮播放/暂停按钮，遥控器直接左右选按钮、确定执行：

| 按键 | 控制栏动作 |
|---|---|
| 左 / 右 | 在按钮之间移动（播放 / 快退 / 快进 / 音量 / 同步 / 清晰度 / 更多） |
| 确定 | 执行当前按钮 |
| 上 | 回到播放/暂停按钮 |
| 下 / 返回 | 收起控制栏（回到全屏） |
| 全屏时的左 / 右 | 快退 / 快进 10 秒（全组一起） |
| 遥控器独立的快退 / 快进键 | 任何时候都快退 / 快进 10 秒 |
| 音量键 | 直接调系统音量（任何时候） |

应用图标和 Android TV 横幅由 `android/tools/gen_brand_assets.py` 生成（Pillow），改配色后重跑即可。
